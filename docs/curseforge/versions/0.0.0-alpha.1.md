<h2>v0.0.0-alpha.1 - Port compiles and boots</h2>

<p>First release of the port under the name <strong>Cataclysm Bosses</strong>. This is a <strong>development alpha</strong>: the mod compiles, the jar builds, the dedicated server boots to <code>Done!</code> and the client loads every resource without a fatal error — but <strong>nothing has been verified in-game yet</strong> (loading a world, summoning a boss, crafting, structure generation).</p>

<blockquote>
<p><strong>Do not expect this to be playable.</strong> Install it only if you want to test loading / report crashes.</p>
</blockquote>

<h3>Status</h3>
<ul>
<li>The entire Java code of the port of <a href="https://www.curseforge.com/minecraft/mc-mods/lendercataclysm">L_Ender's Cataclysm</a> 3.32 (MC 1.21.1) now compiles against Minecraft 26.2 / NeoForge 26.2.0.57 (from a historical baseline of 5,548 compile errors down to 0).</li>
<li>Accessory-slot dependency switched from Curios to <strong>regalia_slots_api</strong>.</li>
<li>The original data pack and assets (~914 + ~1,771 files) are bundled; 210 recipes were migrated to the 26.2 ingredient format.</li>
<li><code>runServer</code> reaches <code>Done (6.2s)! For help, type help</code>; <code>runClient</code> loads without a FATAL.</li>
</ul>

<h3>Known limitations (not playable)</h3>
<ul>
<li><strong>Almost every boss renderer is an empty stub, so the bosses are invisible.</strong> Custom boss bars, the custom health HUD, particle VFX and entity layers (glowing eyes, held weapons, riders) are stubbed. On-player accessory rendering is disabled.</li>
<li>Using the <strong>Cursed Bow crashes the game</strong> (its logic has not been reconstructed). The fusion anvil produces no result.</li>
<li>26.2 worldgen / structures / item-model definitions are unverified — structures may not generate and some recipes/models may be missing.</li>
<li>Custom item rarities, Ignitium Elytra gliding and JEI integration are degraded or disabled.</li>
</ul>

<h3>Fix (startup)</h3>
<ul>
<li><strong>Mixins</strong>: <code>ItemMixin</code> retargeted <code>ItemEntity.hurt</code> &rarr; <code>hurtServer(ServerLevel, …)</code>; <code>FoodDataMixin</code> <code>tick(Player)</code> &rarr; <code>tick(ServerPlayer)</code>; removed <code>NoteBlockInstrumentMixin</code> (its enum target is <code>private</code> now) and <code>Client.HumanoidModelMixin</code> (<code>poseRightArm/LeftArm</code> take <code>HumanoidRenderState</code>), plus 7 unused accessors.</li>
<li><strong>Registration</strong>: <code>ModBlocks</code> (134) and <code>ModItems</code> (282) moved to <code>registerBlock/registerItem(name, factory, propsSupplier)</code> so NeoForge assigns the <code>ResourceKey</code> to the <code>Properties</code> before the block/item is constructed ("Block/Item id not set").</li>
<li><strong>Data components</strong>: <code>AttributeUtils.mergeAttributes</code> now reads from the <code>DataComponentMap.Builder</code> instead of <code>item.components()</code>, which throws "Components not bound yet" during <code>ModifyDefaultComponentsEvent</code>.</li>
<li><strong>Class init</strong>: <code>Ink_Mural_Block</code> holds <code>DeferredBlock</code> handles instead of resolving <code>.get()</code> in <code>&lt;clinit&gt;</code>; <code>Cursed_Tombstone_Block</code> regained its <code>createBlockStateDefinition</code>.</li>
<li><strong>Networking</strong>: <code>MessageOpenInventory</code> referenced client classes from server-loaded code &rarr; moved into the client proxy.</li>
</ul>

<h3>Requirements</h3>
<ul>
<li>Minecraft 26.2, NeoForge 26.2.0.57+.</li>
<li>Dependencies: NautilusAPI, regalia_slots_api.</li>
</ul>
